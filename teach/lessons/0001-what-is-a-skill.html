What Is a Skill?

Lesson 1 of — How Skills Work

This whole directory is a collection of skills. You're standing in a library of them right now. But what is a skill, exactly?

The One-Sentence Answer

A skill is a markdown file (SKILL.md) that tells an AI agent how to do something — a reference guide for proven techniques, patterns, or tools. When an agent faces a task, it can load a relevant skill and follow its instructions.

Skills are how you give an AI agent a playbook. Without a skill, the agent guesses. With a skill, it follows a known good approach.

1. Where Skills Live

Skills are organized as directories with a single SKILL.md inside. OpenCode (and compatible agents) search these locations:

Scope Path
Project .opencode/skills/<name>/SKILL.md
Global ~/.config/opencode/skills/<name>/SKILL.md
Cross-runtime ~/.agents/skills/<name>/SKILL.md
Claude compat ~/.claude/skills/<name>/SKILL.md

The directory you're in (~/Source/skills/) is a collection of skills installed at ~/.agents/skills/ — the cross-runtime alias recognized by OpenCode, Claude Code, Codex CLI, Copilot CLI, and Gemini CLI.

2. The Anatomy of a SKILL.md

Every skill starts with YAML frontmatter — metadata between --- lines:

---
name: executing-plans
description: Use when you have a written implementation plan to execute
  in a separate session with review checkpoints
---

Only two fields are required:

  • name — Lowercase alphanumeric with hyphens. Must match the directory name. 1–64 chars.
  • description — 1–1024 characters. The agent reads this to decide when to use the skill.

Optional fields include license, compatibility, and metadata.

After the frontmatter comes the body — markdown with the skill's instructions. This is what the agent reads and follows when the skill is loaded.

3. Discovery: How Agents Find Skills

When an agent starts, it collects all available skills into a list. It does this by scanning the paths above. Each skill becomes an entry in the agent's skill tool:

<available_skills>
  <skill>
    <name>executing-plans</name>
    <description>Use when you have a written implementation
    plan to execute in a separate session...</description>
  </skill>
</available_skills>

The agent reads the description to decide whether a skill applies. If it does, it calls:

skill({ name: "executing-plans" })

This loads the full SKILL.md into the agent's context, so it can follow the instructions.

4. A Real Example

Let's look at the systematic-debugging skill in this repo:

~/Source/skills/systematic-debugging/
├── SKILL.md
├── condition-based-waiting.md
├── defense-in-depth.md
├── find-polluter.sh
├── root-cause-tracing.md
├── test-academic.md
├── test-pressure-1.md
├── test-pressure-2.md
└── test-pressure-3.md

The SKILL.md file is the skill. The other files are supplementary — reference documents, test scenarios, helper scripts — that the skill can reference. But only SKILL.md is indexed and loaded on demand.

Summary

  • A skill is a SKILL.md file — a reference guide for an AI agent
  • Skills live in skills/<name>/SKILL.md under recognized directories
  • Frontmatter (name + description) is how agents discover which skill to load
  • The body is the actual instruction — markdown the agent follows
