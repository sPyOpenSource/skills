Skill Lifecycle

Print-friendly cheat sheet for reasoning about OpenCode skills

A skill becomes useful through several boundaries. Keep the documented runtime behavior separate from the model's judgment and this repository's conventions.

The Trace

user request
    ↓
discovery paths → SKILL.md files
    ↓
available_skills: name + description
    ↓
model selects a plausible skill
    ↓
skill tool loads the full file (if permitted)
    ↓
agent follows the body and may read companion files

Stage Reference

Stage Question Source of truth
Discovery Is the file in a recognized skill directory? OpenCode searches project and global .opencode, .agents, and .claude paths.
Identification Does the file have valid frontmatter and a matching name? name and description are required; the name matches its directory.
Listing What information can the agent use to choose? The skill tool exposes the name and description in <available_skills>.
Selection Does the request plausibly match the description? Model judgment; a specific description improves routing.
Loading Can this agent access the selected skill? The native skill tool and the configured permission.
Execution What procedure should the agent follow? The body of SKILL.md, plus any referenced files and tools.

Contract Layers

Layer Job Common mistake
name Stable identity and directory match Using a name that differs from the folder
description Routing text: when the skill is relevant Writing a miniature manual instead of trigger conditions
Body Procedure, constraints, and completion checks Leaving the actual instructions in companion files that never get loaded
Companion files On-demand detail, examples, scripts, or references Assuming every companion file is automatically available
Permission Controls whether loading is allowed, denied, or needs approval Debugging selection when the skill is actually hidden

OpenCode vs. Repository Convention

OpenCode documents name, description, license, compatibility, and metadata as recognized frontmatter fields. This repository also uses fields such as version, author, platforms, and nested Hermes metadata. Those fields can serve repository tooling and human readers, but do not assume OpenCode uses them for routing.

Fast Diagnosis

  1. Confirm the file is named exactly SKILL.md.
  2. Confirm it sits in a recognized discovery path.
  3. Parse the frontmatter and compare name with the directory.
  4. Check whether a permission rule hides or blocks the skill.
  5. Read the description as a router, not as the full instructions.
  6. Load the body before judging whether the procedure is complete.
