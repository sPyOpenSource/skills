SKILL.md Anatomy

Reference — print-friendly cheat sheet

Minimal Skill

---
name: my-skill
description: Do this specific thing when that specific condition arises
---

# My Skill

Instructions for the agent go here.

Frontmatter Fields

FieldRequiredRules
nameYes1–64 chars, lowercase alphanumeric + hyphens, must match directory name
descriptionYes1–1024 chars. Agent reads this to decide when to load the skill
licenseNoSPDX identifier (e.g., MIT, Apache-2.0)
compatibilityNoopencode, claude, codex, copilot, gemini, etc.
metadataNoString-to-string map for extra info

Name Validation Regex

^[a-z0-9]+(-[a-z0-9]+)*$

Valid: my-skill, git-release, api-design, test-driven-development

Invalid: My Skill, -my-skill, my_skill, my--skill

Skill Directory Structure

skills/<skill-name>/
├── SKILL.md          ← The skill (indexed + loaded on demand)
├── references/       ← Supplementary docs (optional)
└── scripts/          ← Helper scripts (optional)

How Agents Use Skills

  1. Agent scans discovery paths for skills/*/SKILL.md
  2. Each skill appears in the skill tool's <available_skills> list
  3. Agent reads description fields to decide relevance
  4. Agent calls skill({ name: "<skill-name>" }) to load the full content
  5. Loaded instructions enter the agent's context as a reference

Permissions (opencode.json)

{
  "permission": {
    "skill": {
      "*": "allow",          /* allow all skills */
      "internal-*": "deny",  /* hide internal skills */
      "experimental-*": "ask" /* ask user before loading */
    }
  }
}

Quick Tips

  • The description is a skill's most important field — it's how the agent decides to use it
  • Skills are not always loaded — only when the agent decides they're relevant
  • A skill can have companion files, but only SKILL.md is auto-discovered
  • Skills can reference each other: See <skill-name> for the next step
